# MangoInference 예산 제한 생성

2026-09-18 · ADR-0010

`src.generate.campaign`은 GLM-5.2-FP8, compose_v5 전용의 동기 생성 실행기다. MangoInference Batch 지원을 가정하지 않는다. 사용자와 확정한 전체 계획과 예산을 준비 단계에 넣는다. prepare는 오프라인이며, run만 유료 API 요청을 보낸다.

```bash
.venv/bin/python -m src.generate.campaign prepare \
  --plan <확정한_계획.jsonl> --directory <새_실행_폴더> --budget-usd <확정한_달러_한도>

set -a
source .env
set +a
.venv/bin/python -m src.generate.campaign run --directory <실행_폴더>
.venv/bin/python -m src.generate.campaign export --directory <실행_폴더>
```

## 재현성과 복구

- prepare는 api-main 계획만 선택하고 실제 프롬프트와 계획, 모델·가격·예산, 코드·택소노미·프롬프트 파일 해시를 고정한다. Qwen용 local-check 계획은 별도로 유지한다.
- 한 번에 한 요청씩 실행한다. 요청 전 입력 UTF-8 바이트 수와 여유분, 출력 최대 32,000토큰을 단가로 환산해 보수적으로 예약한다. 반환 사용량을 받으면 실제 사용 토큰에 따른 추정 비용으로 정산한다. 추론 토큰은 출력 토큰에 다시 더하지 않는다.
- 최대 예약 비용까지 포함해 한도를 넘길 요청은 보내지 않는다. 캐시 할인과 제공자 실제 청구는 다를 수 있어 계정 지출의 절대 상한을 보장하는 기능은 아니다.
- 요청 전 state를 디스크에 기록한다. 응답 원문을 저장한 후 사용량과 검증 결과를 정산한다. 프로세스 중단으로 in_flight가 남으면 재개를 거부한다. 먼저 원문·제공자 요청 상태를 확인해야 하며 자동 재시도하지 않는다.
- API 오류 또는 사용량 미반환이면 예약액을 유지한다. 검증 실패도 비용에서 제외하지 않는다. 모든 시도는 문서 ID별로 남고 다음 run에서 같은 ID를 다시 호출하지 않는다.
- 검증 실패 시 stop_reason=quality_gate로 중단한다. 대량 실패를 방치하지 않도록 한 건이라도 먼저 검토한다. 프롬프트나 코드를 수정하면 새 실행 폴더를 준비하며, 완료 문서를 제외한 계획을 명시적으로 만든다.
- export는 반환된 원문을 raw.jsonl로, 검증 통과본만 docs.jsonl로 모은다. 실패·사용량 정보는 state.json에 남는다. 자동 통과본도 사람 검수 완료본은 아니다.

## 제한된 보정 시험

정상 종료했지만 v5 검증에 실패한 원문은 `prepare-repairs --raw <원문.jsonl> --directory <별도_폴더> --budget-usd <한도>`로 별도 준비할 수 있다. 이후 동일한 run/export 경로를 사용한다. 계획과 원문·오류를 고정하고 lineage에 부모 원문 해시와 attempt=1을 기록한다. 이미 보정한 응답과 출력 잘림 응답은 대상에서 제외한다. 비용과 통과율은 최초 생성과 보정을 합산하되 각각 구분해 보고한다 (ADR-0011).

## 프로필 검증 범위

v4/v5의 생년월일·성별·나이는 공통 프로필과 일치해야 한다. 형식은 프롬프트에 지정된 날짜·만 나이를 사용한다. 직원이 작성한 고객 메모는 고객에게 귀속되어야 한다. 주체별 국적에 맞지 않는 신분 식별자는 거부한다.

현재 검증은 자유서술 전체의 일관성·의미 경계·누락 스팬을 보증하지 않는다. 코드가 발견하지 못한 문제도 표본 검수에서 기록하고, 불합격 표본을 임의로 수정해 원본과 섞지 않는다.

## 720건 실행 (ADR-0013)

`.venv/bin/python -m src.generate.production run --directory data/corpus/main-720-v2/0918-05`는 두 흐름을 실행한다. 각 흐름에 $75를 배정하고 최초 생성·1회 보정·미수신 예약을 모두 합산한다. `production report --directory ...`로 현재까지의 원문·통과본·비용을 모을 수 있다. state의 예약액에는 실행 중 요청도 포함되며, 통과본은 완료된 문서만 포함된다.

이번 720건은 전부 API이며 Qwen은 대기하지 않는다. compose_v6에서 접근매체와 상담내용 구분 예시를 보강했다. 실행 중 생성 소스는 수정하지 않는다. 중단 게이트에 도달한 흐름은 점검 없이 재시작하지 않는다.

## 스트리밍 복구 (ADR-0014)

현재 복구 실행기는 `scripts/resume_mango.py`다. 기존 `0918-05` 상태를 초기화해서 재개하지 않는다. `prepare --directory <새 폴더> --plan <720건 계획> --prior <이전 실행 폴더> ...`로 과거 비용과 원본을 연결한 뒤, `run --directory <새 폴더>`로 실행한다. `report --directory <새 폴더>`는 기존 통과본까지 합친 현재 결과를 반환한다.

- 이전 실행·시험·새 시도의 예약 비용을 모두 합쳐 총 $150에서 제한한다. prior로 지정한 상태 파일이 바뀌면 실행을 거부한다.
- 동시 1건, stream=True와 include_usage=True. 16k는 출력 상한 65,536, 나머지는 32,000. 실제 장문 하한 미달은 v7 검증에서 실패한다.
- 일시적 HTTP 오류는 Retry-After 또는 30초 이상 지연 후 한 번 재시도하며 실패 비용은 유지한다. 연결 오류처럼 결과가 불확실한 요청은 자동 재호출하지 않는다.
- 완성된 검증 실패 문서는 동일 계획·원문을 주고 한 번 보정한다. 최대 호출 수는 최초 요청 + HTTP 재시도 1회 + 보정 1회다. 모든 시도가 예산에 포함된다.
- 3개 연속 문서의 서버 실패, 확대된 한도에서도 출력 잘림, 완성본 10건 이후 검증 통과율 70% 미만이면 이유를 나눠 중단한다.
- 부분 본문과 스트림 상태는 각 시도의 partial 파일, 최종 상태는 state 파일, 전체 진행은 progress/summary에 저장한다. 추론 원문은 저장하지 않는다.
