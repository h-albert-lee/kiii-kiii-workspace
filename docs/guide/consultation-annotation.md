# 상담·민원 내용 주석 기준

2026-09-16 · ADR-0006 · taxonomy v1.2 운영 기준

`consultation_content`는 고객 개인의 사정과 구체적인 요청·민원·피해 경위를 담은 구간이다. 상담에서 오간 모든 말을 뜻하지 않는다. 문장만으로 판단하기 어려우면 같은 고객의 앞뒤 발화를 함께 읽는다.

## 포함 여부

| 내용 | 판정 | 이유 |
|---|---|---|
| 급여일이 바뀌어 이자 납부일을 말일로 옮기고 싶어요 | 포함 | 개인 사정과 구체적인 변경 요청 |
| 앱의 계좌관리 메뉴에서 변경할 수 있습니다 | 제외 | 누구에게나 같은 절차 안내 |
| 비밀번호는 다시 말씀하지 마세요 | 제외 | 일반 보안 안내 |
| 퇴직금 입금도 급여 실적으로 보는 건가요 | 문맥에 따라 포함 | 바로 앞에 이 고객의 퇴직·급여 중단이 있으면 개인 상황에 연결된 문의; 일반 상품 FAQ라면 제외 |
| 서면으로 안내받기를 요청함 | 포함 | 고객이 실제로 밝힌 회신 방식 선호 |
| 확인 후 안내하겠습니다 | 제외 | 상담 진행·회신 약속만 있음 |
| 심사 상태는 추가 자료 확인 대기로 분류함 | 포함 | 해당 건의 현재 상태 |
| 서류 발급이 어려운 경우 대체 자료를 검토함 | 제외 | 고객에게 실제 발생했다고 확인되지 않은 가정적 안내 |
| 이번 상담에서 이체를 실행한 것은 아닙니다 | 포함 | 해당 사건의 실행 여부 |

상담사의 업무 문구도 내용으로 판단한다. 해당 고객에게 필요한 특정 증빙, 사례별 심사 판단, 실제 처리 상태는 고객 상황 메모에 해당할 수 있다. 단순 부서 전달·자료 확인 예정·일반 절차는 제외한다. `요청`, `안내`, `확인` 같은 단어만으로 일괄 판정하지 않는다.

## 경계

- 이유와 요청이 함께 있어야 뜻이 완성되면 함께 표시한다. 인사·간투어·화자 라벨은 제외한다.
- 독립된 사실이 여러 개면 각각 나눈다. 사실 사이의 일반 안내는 포함하지 않는다.
- 원문을 고쳐 쓰지 않는다. 절 끝의 연결 어미는 그대로 둔다. 완전한 문장을 포함하는 경우 끝 문장부호가 포함될 수 있으며, 이 차이는 의미 판정과 별도로 다룬다.
- 별도 절에 있는 원인이나 대상을 억지로 하나의 연속 구간에 묶지 않는다. 대명사의 의미는 주변 문맥으로 판정한다.
- 상담내용 태그를 줄이거나 지워도 그 안에 있던 이름·계좌·전화 등 독립된 식별자 태그는 유지한다.

예시:

> OTP는 다시 말씀하지 마세요. **접근매체 정지와 피해구제 신청 안내를 요청하신 것으로 접수할게요**.

굵은 부분만 상담내용에 해당한다. 앞 문장은 일반 보안 안내다.

> **본인 조작이 아닌 출금이라는 진술로 남기고**, 별도 기기로 금융회사에 연락하시도록 안내했어요.

고객의 진술만 남긴다. 뒤의 보안 절차 안내는 제외한다.

## 이번 보정본의 범위

문서 유형별 가장 짧은 문서 총 10건에서 기존 상담내용 태그 64개를 Codex가 검토했다. 원문과 다른 카테고리 태그는 그대로이다. 기존 태그의 포함 여부와 경계를 검토한 것이며, 누락 주석이나 모든 주체 연결을 검증한 완성 gold가 아니다. 10건 중 상담내용 태그가 원래 없는 문서는 3건이다.

결정마다 원래 구간·보정 구간·사유를 `docs/reviews/consultation-calibration-v1.json`에 기록했다. 읽기용 비교본은 `data/corpus/pilot-0.1/review/consultation-calibration-v1/boundary-review.md`이다.

## 독립 검수

사람 검수에는 기준 사례와 겹치지 않는 `consultation-calibration-v1/consultation-iaa30.v2.jsonl`을 사용한다. 각 문서에는 본문과 ID만 있다. 유형별 3건씩 유지했으며, 이전 검수 파일과 섞지 않는다.

검수 전에 원문에 대한 공통 절 분할을 확정하고 두 검수자가 각 단위의 포함 여부를 독립 판정한다. 경계 차이는 별도로 기록한다. 두 결과가 나온 뒤에만 κ를 산출하며, 이 AI 보정본과 생성기 태그의 일치율을 사람 간 일치도로 보고하지 않는다. ADR-0004의 κ<0.6 시 subtype 축소 검토 조건은 그대로 유지한다.
