# 사라 — 문맥 효과 연구 담당 / 에이전트 시작 문서

2026-09-23. 담당: **사라**. 상태: **배정 완료, 분석 착수 전**. 사용자는 사라에게 기존 전체 문맥 대 지역 문맥 비교의 연구 설계·통계 검증·오류 해석·논문 집필을 맡겼습니다. 모델 실행 담당자의 보조 업무가 아니라 **핵심 연구 질문 하나를 책임지는 역할**입니다.

## 연구 질문과 범위

**동일한 한국 금융 문서의 동일한 개인정보를 추출할 때, 전체 문맥을 제공하면 지역 문맥만 제공할 때보다 탐지가 개선되는가? 그 효과는 어떤 조건에서 달라지는가?**

기존 4개 LLM의 `full_context_targeted` 대 `local_window` 결과를 사용합니다. 새 모델·새 추론 조건·추가 유료 호출을 늘리지 않습니다. 3개 baseline은 주 성능표의 비교 기준이며 동일한 문맥 ablation 쌍은 아닙니다. 전체 실험은 7개 시스템·11개 조건을 유지합니다.

책임 범위:

- 검증할 가설, 주/보조 분석, 통계 절차, 오류 분석 기준을 결과 확인 전에 정리하고 고정합니다.
- 완성된 paired 결과를 분석하여 효과 크기·불확실성·실패 양상을 해석합니다. 개선, 악화, 뚜렷한 차이 없음 모두 유효한 결론입니다.
- 재생성 가능한 표·그림과 논문 결과/논의 초안을 작성합니다. 무엇을 본문에 넣을지 근거를 제시합니다.
- 분석 코드와 산출물을 GitHub에 커밋·푸시합니다. 실제 모델 실행은 성현/은빈/한울이 맡습니다. 공통 cohort 운영·취합 담당은 아직 별도 미정이며 사라에게 자동 배정된 것이 아닙니다.

## 결과가 없어도 지금 시작할 작업

1. `docs/research/context-analysis-plan.md`에 분석 계획 초안을 작성합니다. 연구 질문, 주 추정량, 가설, 층화 기준, 오류 표본 선정 방식, 비교 횟수/불확실성 해석을 담고 git commit으로 고정합니다. 고정 시점과 그전에 실제 detector 결과를 보았는지도 기록합니다. 이는 레포 내 사전 분석 계획이며 외부 사전등록이라고 표현하지 않습니다.
2. `scripts/analyze_context_effect.py` 등 별도 분석 도구를 구현합니다. 완성된 result 경로 목록을 명시적으로 받고, pairing·해시·완료 여부를 확인한 뒤 CSV/통계 JSON을 출력하게 합니다. 기존 채점 함수를 재사용하고 평가 실행기·prompt는 변경하지 않습니다.
3. 합성 fixture로 양/음/무차이, 문서 순서 변경, 누락/중복 ID, 다른 cohort, 미완료 run 거부, 실패 요청의 FN 유지와 micro 집계를 검증합니다. 예시 숫자를 실제 결과 폴더나 논문에 남기지 않습니다.
4. `figures/src/`에 최종 분석 파일을 입력받는 그림 스크립트를 준비합니다. 빈 데이터는 빈 결과/명확한 대기 상태로 처리하고 가상 성능 곡선을 실제 결과처럼 만들지 않습니다.
5. 계획·코드·필요 artifact 목록을 푸시하고 이 문서 또는 배정표에 commit/PR 링크를 남깁니다. 결과 대기만 하면서 중단하지 않습니다.

파일명은 권장 경로이며 기존 작업과 충돌하면 조정할 수 있습니다. 통계적 결정을 구체화하고 분석 코드를 구현하는 것이 사라의 첫 과업입니다. 아래는 이미 고정된 프로토콜과 분석의 경계입니다.

## 분석 원칙

### 주 분석

- 각 LLM별 **Δ strict micro F1 = full − local**. 같은 문서들의 TP/FP/FN을 합쳐 micro F1을 계산합니다. 문서별 F1 평균이나 모델 평균을 주 추정량으로 대체하지 않습니다.
- 동일 데이터/taxonomy 해시, 동일 문서 ID 집합, core/halo/output 제한, 동일 모델 revision 및 sampling/reasoning 설정, 공통 cohort gate를 확인합니다. 미완료/pilot/smoke 결과는 거부합니다. 메타데이터가 가려졌다면 필요한 조건 일치 근거를 담당자에게 요청합니다.
- 기존 `src.eval.run compare`는 문서 단위 paired bootstrap, 2,000회, seed 0이며 첫 파일에서 둘째 파일을 뺍니다. 이를 기본 절차로 활용하고 조건/모델 설정 확인을 분석 진입부에서 보완합니다. 모델 쌍을 독립 문서처럼 합쳐 표본 수를 늘리지 않습니다.
- 4개 모델의 구간은 우선 **모델별 pointwise 95% interval**로 명시합니다. 전체 모델에 대한 유의성 주장이나 다수의 하위군 검정을 할 경우 다중 비교 처리 방법을 계획에서 먼저 정합니다. 0 포함 여부만으로 동등성이나 효과 부재를 주장하지 않습니다.
- 문서 간 원본 공유/연계 등 독립성 문제가 있는지 공개 provenance로 점검합니다. 군집 의존성이 확인되면 cluster 단위 재표집 설계를 별도 ADR로 기록합니다. 확인되지 않은 독립성이나 군집 ID를 만들어내지 않습니다.

### 보조 분석

- 문서 길이, 정보주체 수, T0–T3, 카테고리별 차이를 탐색합니다. 표본/정답 스팬 수를 함께 보고하고 작은 하위군에서 강한 결론을 내리지 않습니다.
- 문맥 의존 카테고리 묶음을 쓴다면 taxonomy 정의를 근거로 결과를 보기 전에 목록을 고정합니다. consultation_content 등에서 차이가 날 수 있다는 것은 가설이지 이미 확인한 발견이 아닙니다.
- 생성기(GLM/Astra)별 차이도 민감도 분석으로 확인할 수 있습니다. 관찰된 상관을 문서 길이/주체 수의 독립적인 인과 효과로 단정하지 않습니다.
- 실패/잘림/거부/형식 오류는 주 분석에 그대로 포함합니다. full에서만 실패한 요청이 많다면 이를 문맥 효과 해석에 포함합니다. 성공 사례만 비교한 분석은 보조로 명시하며 주 결과를 대체하지 않습니다.
- 같은 최대 출력 한도와 partition이라도 full/local의 입력량·비용은 다릅니다. 이 비교를 동일 계산 예산 실험으로 주장하지 않습니다. 본 실험은 전체 문서를 한 번에 출력하는 방식이 아니라 고정 TARGET별 추출이라는 점을 설명합니다.

### 오류 분석

- raw 응답과 gold/prediction 대조가 필요합니다. result.json의 합계만으로 오류 원인을 추정하지 않습니다.
- 문맥으로 회복된 누락, full에서 새로 발생한 과잉 탐지, 카테고리/경계 오류, 기술적 실패 등을 구분하는 rubric을 먼저 정합니다. 표본 수·선정 기준·seed·분모를 기록합니다.
- 개인/조직 식별 혼동이나 정보주체 귀속 문제는 증거가 있을 때 정성 사례로 설명합니다. 현재 출력은 subject ID를 예측하지 않으므로 귀속 정확도를 측정했다고 주장하지 않습니다.
- 대표 사례와 빈도 추정용 표본을 구분합니다. 보기 좋은 사례만 고른 뒤 전체 오류 분포로 일반화하지 않습니다. gold 의심 사례는 별도 목록으로 보고하고 고정 test 라벨을 조용히 수정하지 않습니다.

## 4페이지 원고에 넣을 범위

페이지 제한은 프로젝트의 **본문 4페이지(참고문헌 제외)** 기준으로 설계합니다. 기존 taxonomy/생성/평가 방법 설명의 공간도 필요하므로 사라의 작업을 별도 대형 실험 섹션으로 추가하지 않습니다.

- **주 성능표 1개:** 7개 시스템을 담고 LLM의 full/local F1을 나란히 배치합니다. baseline의 local 칸은 해당 없음으로 표시합니다. Δ/구간을 같은 표에 넣을지는 실제 지면을 보고 결정합니다.
- **분석 그림 최대 1개:** 기본 후보는 T단계별 성능/문맥 효과입니다. 세부 패널·모델 수는 판독성과 지면에 맞춰 줄입니다. 어느 그림을 본문에 쓸지 바뀌면 선택 이유를 기록하고 전체 계획 분석은 저장소에 보존합니다.
- **결과·논의 약 1–2문단:** 주 효과, 중요한 조건 차이, 한계 또는 대표 오류를 설명합니다. 통계표·추가 길이/주체/카테고리 분석은 GitHub에 공개합니다. appendix가 별도 허용된다고 가정하지 않습니다.
- 실제 원고 전체를 컴파일해 본문 4페이지 안에 드는지 확인합니다. 제출 전 venue 지침은 별도 재확인하며, 분석 담당이 현재 지침을 확인했다고 미리 주장하지 않습니다.

표·그림·짧은 해석을 준비하는 것이 목표이지 특정 긍정적 결론을 만드는 것이 아닙니다.

## 산출물과 완료 기준

- 사전 분석 계획 및 변경 이력: `docs/research/context-analysis-plan.md`.
- fixture로 검증된 분석/그림 코드와 사용 명령. 실제 결과가 없으면 준비 완료·결과 대기로 표시합니다.
- 실제 결과가 도착하면 `experiments/results/analyses/<analysis-id>/`에 입력 목록/해시, 분석 설정, 통계 JSON, 표 CSV, REPORT를 저장하고 푸시합니다. 그림은 재생성 가능하게 보관합니다.
- 본문용 영문 결과·논의 초안: `docs/research/context-results-draft.md`. 모든 수치/주장은 해당 artifact로 추적 가능해야 합니다. 결과 전에는 구조만 작성합니다.
- 논문 반영은 공저자 검토와 Overleaf 코멘트 보존 절차를 거칩니다. 처음부터 paper 파일을 교체하지 않습니다.

완료는 전체 계획 분석과 해석이 재현 가능하고, 4페이지 안에서 사용할 표·그림·문단이 준비되어 GitHub에 공유된 상태입니다. 추가 유료 실험이나 데이터/평가 프로토콜 변경이 필요해지면 별도 제안·ADR로 분리합니다.

## 사라의 에이전트에게 전달할 요청

> 이 레포의 AGENTS.md와 docs/research/sara-context-analysis.md를 읽고, 사라가 담당하는 전체 문맥 대 지역 문맥 효과 연구를 시작해줘. 먼저 결과를 보지 않은 상태의 분석 계획을 작성·고정하고, 기존 result 스키마를 이용하는 분석 코드와 fixture 테스트, 재생성 가능한 표/그림 코드를 준비해서 GitHub에 커밋·푸시해줘. 성현·은빈·한울의 모델 실행을 중복하지 말고 기존 11개 조건을 활용해. 실제 결과가 아직 없으면 수치를 만들지 말고 준비 작업을 완료해줘. 결과가 들어오면 모델별 paired 분석·오류 해석을 수행하고, 본문 4페이지에 들어갈 주 표 1개·그림 최대 1개·짧은 영문 결과/논의 초안을 마련해줘. 상세 분석도 GitHub에 남겨줘.
