## 실패 원인과 해석

- DeepSeek: 지원하지 않는 은행 옵션 `토스`, `한빛` 때문에 2건 실패. 보험금 청구서 1건은 `남성`, `하나정형외과의원` 같은 짧은 속성 태그가 현재 최소 2어절 규칙에 걸렸다. 장문 2건은 각각 출력 32,000토큰을 사용하고 본문이 비어 있었다.
- GLM: 4건은 속성 태그 열기/닫기 형식 불일치. 예를 들어 `[[consultation_content:1|subtype=complaint_reason]]`은 파서가 기대하는 `[[category:subject:subtype]]` 형식과 다르다. 대출 약정서 1건은 `60%` 속성 태그의 최소 길이 오류, 증권 보고서 1건은 본문이 반환됐지만 한도 종료 및 짧은 속성 태그 오류였다. `kf-00007` KYC 서식 1건이 자동 검증에 통과했다.
- 현재 프롬프트에는 지원 은행 전체 목록과 subtype 문법 예시가 충분하지 않다. 짧은 태그 거부도 현재 생성 규칙에 따른 것이므로 모든 거부를 문장 품질 불량으로 해석하지 않는다.
- 자동 검증 통과는 의미적 정확성이나 사람 검수 완료를 뜻하지 않는다. 참조된 주체와 실제 슬롯의 연결, 금융 문서의 자연스러움, 생성된 주민번호와 본문의 생년월일 일관성 등은 별도로 확인해야 한다.
- 제공자 반환 추론 사용량은 DeepSeek 103,993 / 출력 111,839토큰, GLM 77,206 / 출력 110,766토큰이다. 추론은 출력 사용량에 포함되며 비용에 중복 가산하지 않았다. DeepSeek 한 응답은 추론 32,003·출력 32,000으로 3토큰 차이가 있어 제공자 값 그대로 보존했다.

즉시 Astra를 교체하기에는 현재 설정의 성공률이 낮다. 태그 문법 안내와 추론 예산 제어를 보완한 후 소량 재시험할 가치는 있으나, 이번 결과만으로 두 후보의 최종 우열을 정하지 않는다. 기존 Astra 80건과 Qwen 20건 계획은 유지한다 (ADR-0008).
