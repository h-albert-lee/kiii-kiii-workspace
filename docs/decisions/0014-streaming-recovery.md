# ADR-0014: 스트리밍과 출력 예산으로 720건 생성 복구

- 날짜: 2026-09-18
- 상태: accepted (실제 장문 시험 통과 후 본 생성 재개)
- 대체 범위: ADR-0013의 비스트리밍 전송, 일괄 32k 출력 한도, 오류 통합 통과율, 재시도 금지

## 확인한 원인

0918-05는 14건 시도 중 6건 완성·검증 통과, 6건 HTTP 502/503, 2건 finish_reason=length였다. 잘린 두 응답은 각각 출력 32,000토큰 중 reasoning 23,569/27,021토큰을 사용했다. 완성 응답의 태그 검증 실패가 이번 중단 원인은 아니다. 기존 quality_gate는 전송 실패까지 분모에 넣어 상태명을 오해하기 쉬웠다.

[공식 추론 문서](https://inference.mangoboost.io/docs/guides/reasoning/)에는 추론량을 낮추는 제어가 현재 지원되지 않는다고 명시되어 있다. [공식 오류 처리 문서](https://inference.mangoboost.io/docs/guides/reliability-and-error-handling/)는 장문 스트리밍과 일시적 오류의 제한된 지연 재시도를 권고한다. 502의 개별 내부 원인을 로그만으로 확정하지 않는다.

## 결정

- 스트리밍으로 전환하여 부분 본문·수신 진행률·요청 ID·trace ID를 디스크에 보존한다. 추론 원문은 저장하지 않는다. 정상 finish_reason과 최종 usage가 없는 응답은 완성본으로 취급하지 않는다.
- 16k 문서는 최대 출력 65,536토큰, 나머지는 32,000토큰을 예약한다. 이는 본문 목표 길이를 바꾸는 것이 아니라 추론과 태그를 포함한 생성 여유다.
- stream_options.include_usage는 실제 호출에서 사용량 수신 여부까지 확인한다. 문서에 없는 추론 제어 필드가 작동한다고 가정하지 않는다.
- 동시 실행 1건으로 줄인다. HTTP 429/500/502/503/529만 지연 후 최대 한 번 재시도한다. 첫 실패의 비용 예약을 유지하고 추가 요청도 별도 예약한다. 상태를 모르는 연결 오류는 자동 재시도하지 않는다.
- 서버 오류, 출력 한도, 완성본의 주석 검증 실패를 별도 집계한다. 실제 완성본의 검증 통과율을 품질 게이트로 사용한다.
- 기존 6건·성공한 복구 시험 문서를 보존하고 같은 문서 ID를 중복 생성하지 않는다. 이전 실행·시험·새 실행의 추정 사용액과 불확실 예약을 합쳐 $150 한도를 적용한다.
- 720개 원래 계획은 유지한다. 복구 시험에서 실제 16k 길이·완성 여부·검증·사용량 수신을 확인한 후 나머지 계획을 재개한다. 기존 응답/상태는 덮어쓰지 않는다.

## 한계

스트리밍은 공급자의 용량 부족이나 장애를 해결하지 않는다. 출력 여유 확대도 모델의 장문 준수를 보장하지 않는다. 반복 오류는 원인별로 중단하고 상태를 명시한다. 자동 검증 통과와 사람 검수는 구분한다.

## 장문 최소 분량 보강

첫 스트리밍 시험은 42,802 출력 토큰(reasoning 31,771), 509초, finish_reason=stop·usage 수신·태그 검증 통과로 끝났다. 추정 비용 $0.187249. 그러나 실제 본문은 근사 8,735토큰으로 16k 구간 하한 9,000에 미달했다. 이 결과를 장문 성공으로 보고하지 않는다.

compose_v7은 장문 본문 20,000~26,000자와 내용 배분을 명시하고, 16k 계획이 실제 16k 구간에 들지 않으면 검증 실패로 처리한다. 기존 v6의 한 구간 길이 차이 허용은 보존하되 새 생성에는 적용하지 않는다. 첫 스트리밍 시험의 원문과 비용은 보존하고, 장문 완료 건수에서는 제외한다. 일반 문서 길이 기준과 택소노미는 변경하지 않는다.
