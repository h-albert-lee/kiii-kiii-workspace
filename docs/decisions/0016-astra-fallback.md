# ADR-0016: Mango 추가 시도 후 Astra low Batch로 전환

- 날짜: 2026-09-20
- 상태: accepted (조건부 전환 승인, 아직 OpenAI 제출하지 않음)

사용자가 현재 제공자로 조금 더 시도하고 실패가 계속되면 GPT-6 Astra light로 전체 생성하라고 지시했다. OpenAI에 $100 충전했다고 알렸다. 공식 모델 문서상 별도 light 모델/추론 값은 확인되지 않아 `gpt-6-astra`와 `reasoning_effort=low`로 해석한다. 기존 사용자 선호대로 Batch 경로를 사용한다.

현재 recovery-0920-01을 계속 실행한다. 출력 한도를 확대한 뒤에도 출력 잘림, 반복 서버 오류 또는 낮은 완성본 검증 통과율로 다시 중단되면 반복적인 Mango 튜닝 대신 Astra 전환을 우선한다. 정상 진행 중에는 전환하지 않는다. 주기적 LLM 모니터링은 만들지 않는다. 현재 실행기에 자동 OpenAI 제출 기능은 없으며, 전환 시 실제 제출·예산 보호를 별도로 구현/검증해야 한다.

OpenAI 지출 한도는 충전액을 보수적으로 해석해 $100로 둔다. 이는 Mango의 기존 $150 상한과 별도이며, 잔액을 도구로 검증한 것은 아니다. $100 초과 지출은 승인된 것으로 취급하지 않는다.

기존 Astra v2 파일럿 80건 비용 환산 $31.42를 단순히 720건과 Batch 50% 할인으로 외삽하면 약 $141.39다. 새 v7 프롬프트 길이와 문서 분포가 달라 이 수치는 견적이 아니며, $100에 전체 완료를 보장할 수 없다. 전환 시 소량 실제 토큰 사용량으로 갱신하고 예산 내 분할 제출한다.

사용자의 “전부”를 Astra 단일 생성기 코퍼스 요청으로 우선 해석한다. 기존 GLM 결과는 삭제하지 않고 비교 자료로 보존하며, Astra 결과와 몰래 혼합해 720건을 채우지 않는다. 2160건 확대는 여전히 별도 판단한다.
