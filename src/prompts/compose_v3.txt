당신은 한국 금융회사(은행·증권·카드·보험) 내부 문서를 사실적으로 작성하는 작가입니다. 아래 계획에 맞는 **가상의** 문서 한 편을 한국어로 작성하세요.

## 절대 규칙
1. 개인 식별자(이름, 주민등록번호, 계좌·카드·전화번호, 이메일, 주소, 고객번호, 계약번호, 비밀번호 등)는 **직접 쓰지 말고** 반드시 슬롯으로 씁니다. 숫자 식별자를 슬롯 없이 쓰면 문서는 폐기됩니다.
2. 슬롯 문법: `{{카테고리:주체}}`. 주체는 고객이면 1, 2, 3…, 상담사·직원이면 staff1, staff2…, 제3자(가족 등)면 tp1, tp2….
   - 같은 사람의 같은 식별자는 문서 내에서 항상 같은 슬롯을 다시 씁니다 (예: `{{bank_account_no:1}}`를 두 번).
   - 옵션: `{{person_name:1|given}}` 이름만 부를 때 / `{{bank_account_no:1:bank=신한}}` 은행 지정 / `{{rrn:1|masked}}` 부분 마스킹 표기 요구 시.
   - 은행 지정은 bank_account_no 슬롯에만 쓰며 bank 값은 다음 정확한 표기만 허용합니다: {supported_banks}. 약칭(KB, 토스, SC 등)·지점명·임의 은행명을 bank 값으로 넣지 마세요. 예: 토스뱅크 계좌는 `{{bank_account_no:1:bank=토스뱅크}}`. 증권 계좌에는 은행 옵션 없이 `{{securities_account_no:1}}`를 씁니다.
   - 고객 번호는 계획의 1~{num_subjects}만 사용합니다. 계좌 소유자·연락처 주인·화자와 슬롯 주체를 일치시키세요. 같은 사람은 재언급해도 같은 주체 번호를 사용하며, 서로 다른 고객의 식별자를 편의상 공유하지 마세요.
   - 구조 지시(계획에 있을 때만): `{{bank_account_no:1|split=2}}` 와 `{{bank_account_no:1|split=2,part=2}}` — 하나의 번호가 두 발화·두 줄에 나뉘어 나오는 상황. `{{phone_no:1|readback}}` — 상담사가 고객이 말한 번호를 되읽는 위치.
3. 식별자가 아닌 개인정보(대출 조건, 거래 내역, 연체, 소득·직업, 신용점수, 건강 등 민감정보, 생년월일·연령, 성별, 국적, 가족관계, 직장·직위, 학력, 생애 사건, 투자성향, 상담·민원 내용, 이용 패턴, IP·기기, 지역 언급)는 자연어로 쓰되 `[[카테고리:주체]]…[[/카테고리]]`로 감쌉니다. 태그는 중첩하지 않고, 절 단위(2어절 이상)로 감쌉니다. 태그 안에 슬롯이 들어갈 수 있습니다.
   - 속성 태그에 subtype을 붙일 때는 콜론으로만 구분합니다: `[[consultation_content:1:complaint_reason]]이체 지연으로 생활비 사용이 곤란하다는 민원[[/consultation_content]]`. 닫는 태그에는 카테고리만 씁니다. `|subtype=...`, `|full_dob`, `:subtype=...`는 속성 태그 문법이 아닙니다. subtype이 불확실하면 생략하세요.
   - 태그 내부에는 의미가 완결되는 개인정보 절을 최소 2어절로 넣습니다. 예: `[[gender:1]]성별은 남성으로 기재[[/gender]]`, `[[financial_capacity:1:debts]]담보인정비율 60% 적용[[/financial_capacity]]`. 숫자·명사 한 단어만 감싸지 말고 해당 정보의 서술까지 포함하세요. 일반적인 절차 안내는 상담내용 태그에 넣지 마세요.
   - 목록의 subtype은 위 속성 태그 형식에만 사용합니다. 이 프롬프트에서 설명한 식별자 슬롯 옵션 이외의 옵션은 만들지 마세요.
4. 사용 가능한 카테고리 id는 아래 목록만. 목록에 없는 id를 쓰지 마세요.
5. 은행·증권사·상품명은 실제 이름을 자유롭게 써도 됩니다(공개 정보). 실제 인물은 등장시키지 마세요.
6. `{{NEG}}` 표시를 {neg_count}곳에 넣으세요. 각 표시는 태그 바깥의 독립된 줄 `공통 참고정보: {{NEG}}`로만 씁니다. 속성 태그 안에 넣지 마세요. 실제 치환값은 공개 기관명, 날짜, 예시 번호, 일반 상품 조건 중 하나이므로 앞뒤에 특정 종류를 단정하는 말(운송장, 계좌번호 등)을 붙이지 마세요.
7. 출력은 문서 본문만. 설명·머리말·코드블록 금지.
8. 현재 변형 레벨은 {variation_level}입니다. {level_constraints}
9. 분량은 슬롯과 태그를 제거하고 값으로 치환한 본문 기준입니다. 같은 안내를 반복해 길이를 채우지 말고, 각 문서 유형에 맞는 구체적인 항목·경과·거래로 구성하세요.
